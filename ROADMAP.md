# Roadmap

Delivery tracking for Gantry v4. One checkbox per implementation issue, grouped into **execution waves**:
wave N contains exactly the issues whose blockers all sit in waves below N, so each wave is one round of
parallel implementation (one `/asdlc wave:N` run) and the blocker graph is a DAG by construction.

**Each issue's `Status:` line is authoritative for that issue.** This roadmap is a projection of the issue
files, regenerated by `python3 .agents/skills/asdlc/scripts/roadmap.py`. When the two disagree, the issue
wins and this file is stale — regenerate it.

- Specs: `.scratch/<slug>/spec.md`
- Issues: `.scratch/<slug>/issues/NN-<slug>.md`
- Cross-spec references, settled decisions and the 2026-09-12 dependency-graph repair:
  [`.scratch/gantry-v4/slice-index.md`](.scratch/gantry-v4/slice-index.md)

## How to update this file

When an issue is completed, run `roadmap.py done <spec#NN>`. It ticks the issue's acceptance criteria,
sets `Status: done`, ticks the checkbox here and refreshes every counter in one pass. Doing the same by
hand is allowed but must produce the same result: `roadmap.py check` reports any drift and must be clean.

When a blocker changes or an issue is added, run `roadmap.py waves`: the wave layout below is derived from
the blocker graph and is never edited by hand. The script refuses to render a graph with a cycle.

Do not tick an item here without setting `Status: done` in the issue, and do not tick an item whose
acceptance criteria are not all met. A partially delivered slice stays unticked — the whole point of a
vertical slice is that it is demonstrable on its own, so "mostly done" is not a state this file records.

## Where work can start

Wave 0 is the only place: `release-engineering#01` (the repository bootstrap — there is no `package.json`,
no `src/`, and no CI, and all 18 other specs inherit its toolchain choices) and `machine-setup#02` (the
harness compatibility matrix, validated data plus a detection function, depending on nothing).

Waves 1 and 2 are dominated by `release-engineering` and the two foundation seams everything else
consumes: `data-handling#01` (the redaction sink interface) in wave 1 and `execution-core#01` (the shared
operation core seam) in wave 2. The critical path is 19 waves long; the widest waves (7 to 13) carry
between 9 and 14 independent issues each, which is where parallel rounds pay off most.
